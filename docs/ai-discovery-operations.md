## Crawl reliability evidence

The product routes are statically generated by Next.js and the observed apex homepage response was a Vercel cache hit behind Cloudflare. The `www` host returned a permanent redirect to the apex host.

Cloudflare's Email Address Obfuscation feature previously rewrote public HTML email links to `/cdn-cgi/l/email-protection`, while the helper path returned HTTP 404 to the crawler test. Commit `5282fa9` now wraps only UPG's public email output in Cloudflare's documented `email_off` comments. Fresh production proof across all 87 sitemap pages found the direct email text and `mailto:` links, with no `data-cfemail` or `/cdn-cgi/l/email-protection` link left in rendered HTML. The zone-wide security setting and cache policy were not changed.

The operator network also produced intermittent TLS failures and 12-second timeouts for product-page requests using OAI, Claude, Perplexity, Bing, and Google user agents. This does not prove a worldwide origin or crawler failure. Re-test with PageSpeed and independent regions before changing caching or CDN behavior.

An external search result checked on 2026-08-12 still showed an older homepage snapshot with retired products, old MOQs, and old geographic wording. Faster change notification and recrawl monitoring are therefore required.

## IndexNow

IndexNow notifies participating search engines that a URL changed. It does not guarantee a crawl or indexing.

The public ownership key is:

`https://universalpackaginggroup.com/75e2b2f10c82e360acc19a29a8670919.txt`

After the key file is deployed, submit every canonical URL from the live sitemap:

```bash
npm run indexnow:submit
```

Preview a submission without contacting IndexNow:

```bash
npm run indexnow:submit -- --dry-run --url / --url /products/custom-tuck-boxes
```

Submit one or more changed URLs after their production deployment is live:

```bash
npm run indexnow:submit -- --url /products/custom-tuck-boxes --url /faq
```

The script accepts only canonical URLs on `https://universalpackaginggroup.com`, verifies the published ownership key before a real submission, removes duplicates, and treats only HTTP 200 or 202 as accepted.

Official protocol reference: [IndexNow documentation](https://www.indexnow.org/documentation)
